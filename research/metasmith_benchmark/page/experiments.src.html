Five benchmark experiments

Each panel is one run with its own driver. There are three kinds of experiment: reproduce a published result, show metasmith has parity with a reference pipeline, and run the metasmith optimized pipeline. The page has three sections: datasets, the five experiments, and the tools E5 swaps. Each panel opens its solved workflow on request.

E1–E4 and the E5 pilot launch together

First runs are expected to crash, and running all five at once surfaces every fix sooner. Samples split into batches within an experiment only if the estimated peak file count exceeds fir's project inode quota of 1 M. Drivers run as compute-node jobs where they can (METASMITH_DRIVER_SLURM=1).

CAMI 2+3 through nf-core/mag, short and long reads

Goal: run somebody else's pipeline as itself, using long reads where CAMI has usable ones, scored against ground truth. This is the reference point for every parity claim.

Datasets

  • All 249 CAMI 2+3 samples, one read type each (see Datasets)
  • Long, 41 samples: plant-associated Nanopore (21) and CAMI III human gut Nanopore (20)
  • Short, 208 samples: marine, strain, three toy sets

Driver

  • nf-core/mag 5.5.0 at revision 56abab5b, control.config, Slurm on fir
  • Short lane: fastp → MEGAHIT → bowtie2. phiX removal is off
  • Long lane: Porechop ABI → Chopper → Flye → minimap2
  • Both lanes: MetaBAT2 / SemiBin2 / COMEBin → DAS Tool → CheckM2

Targets / metrics

  • contig_to_bin_map.tsv, DAS Tool bins
  • AMBER on the consolidated bin set, via score_reference_amber.py
  • CheckM2 completeness and contamination
  • Wall time and core-hours per stage

Proven

  • Rung 1 (marine_sample_0) wrote 50 MetaBAT2 bins at min_contig_size 1500
  • A failed DAS Tool fails the run instead of exiting zero with empty tables
  • A mixed short/long sample sheet validates and previews through both lanes
  • Flye on the long lane
  • keep_phix = true switches phiX removal off
  • Sample sheets come from E2's own sample list: 208 short-read samples on split R1/R2 pairs (all 208 split and checked against their sources), 41 long-read samples
  • Each sheet runs as its own Nextflow head in a Slurm job, run_e1.sbatch, offline against the pre-pulled images
  • Both arms are finished. The short arm completed clean on 2026-09-17: exit 0, 3,678 tasks succeeded and 3,185 cached, 96 failures all re-submitted and none terminal, BIN_SUMMARY and MULTIQC both exit 0. MAG_DEPTHS closed at 832/832 — four bin groups across 208 samples

Open

  • No DAG yet. Wave 1's heads write one with -with-dag
  • E1 is archived and its trees released: e1_long.tar (13,787 members) and e1_short_out.tar (57,253 members), each verified member-for-entry before anything was deleted. Both tars still sit on fir's scratch, so there is no off-site copy yet

The same pipeline, driven by metasmith

Goal: match E1 exactly except for the driver: same samples, same read type per sample, same tools, same parameters. Any difference in the AMBER score then belongs to the driver.

Datasets

  • The same 249 samples as E1, checked name for name, with the same read type per sample

Driver

  • drivers/e2_cami.py binds only library/transforms/e2: 16 transforms written from nf-core/mag 5.5.0's own commands, arguments and image tags
  • Short arm, 208 samples on E1's split R1/R2 pairs: 15 steps, wave-3 key MjMN02CK. FastQC raw and trimmed → fastp → MEGAHIT → bowtie2 → MetaBAT2 / SemiBin2 / COMEBin → DAS Tool; CheckM2 on all four bin sets; AMBER on all four bin sets
  • Long arm, 41 samples: 14 steps, wave-3 key VgUw0A7c. Porechop ABI → Chopper → Flye → minimap2, then the same tail. Flye and minimap2 take their presets from the platform in each sample's read metadata
  • Not run, because nothing scored reads them: QUAST, NanoPlot and nf-core's standalone Prodigal
  • Runs as a Slurm job on fir through submit_driver.sbatch, 10 cpus / 48 GB

Targets / metrics

  • das_tool_amber_results against E1's AMBER on the same gold standard
  • Tool-for-tool diff with zero unexplained rows
  • Every parity pin read from the rendered .command.out
  • Wall time and core-hours against E1

Proven

  • Rung 1 on the earlier library (iy8YLaGr): MetaBAT2 wrote 51 bins and SemiBin2 57, products inspected
  • Flye --nano-raw on plant sample 0: 1 h 06 m, 3,186 contigs, N50 96,428, peak memory 32.68 GiB. NanoSim reads align at 15.4% error despite their flat Q40 qualities
  • Wave 2 ran both arms to completion: every step on all 208 short and all 41 long samples, with AMBER scoring each sample against its own gold standard and no unbinned pseudo-bin
  • Wave 3 scores all four bin sets. Median f1_score_bp, short arm, 208 samples: COMEBin 0.190, MetaBAT2 0.139, SemiBin2 0.126, DAS Tool 0.089. Strain madness is lowest (COMEBin 0.121, DAS Tool 0.031) and gastrointestinal/oral highest (0.538, 0.393). E1's DAS Tool on marine_sample_0 scores 0.224
  • Median f1_score_bp, long arm, 41 samples: COMEBin 0.903, SemiBin2 0.471, MetaBAT2 0.414, DAS Tool 0.195. E1 long's sample 0 gives the same order (0.885, 0.428, 0.478, 0.18)
  • DAS Tool scores below its best input on 208 of 208 short samples. At score_threshold 0.5, nf-core/mag's default, it keeps high-precision bins (precision 0.957 short, 0.952 long) and drops most of each genome (assigned bp 0.295 short). The wave-1 figure of 0.91 scored DAS Tool's unbinned set as a bin and is withdrawn

Open

  • The first 1-sample probe proved the Slurm driver path, and its fastp wrote nothing: --detect_adapter_for_pe fails silently on interleaved input. The short arm now reads the split pairs, and probe Gu9VJmwO on them passed: fastp wrote 4.55 GB of trimmed reads, and FastQC its reports
  • Each lane's images are fetched by a --materialise job before wave 1
  • Flye declares 64 GB, 1.9× its four measured peaks. Both long-read datasets declare OXFORD_NANOPORE, which for CAMI III toy human gut is an inference

Pratama 2026 groundwater virome

Goal: recover Pratama's published vOTUs with our own tools. Assemble every run, pool the viral calls from every assembly with each contig still marked by sample, curate and cluster the pool to vOTUs, and score the result against the paper's 257,252 vOTUs of 5 kb or more. The target is their results, not a literal re-run of their commands.

Decided

Viral only: E3 stops at vOTUs. The MAG half (binning, refinement, dRep, GTDB-Tk, DRAM) and the annotation tail (vConTACT3, DRAM-v, iPHoP, spacers, MetaPop) are out of scope. E1 and E2 cover metagenomic assembly and binning.

Nanopore runs: do what Pratama did. Each well's one 0.2 µm MinION run pairs with every 0.2 µm 2022 Illumina replicate from that well in a hybrid metaSPAdes --nanopore assembly: 3 each for H14, H32, H41, H52 and H53, and 2 for H51, which gives the paper's 17.

Curation: the keep rules of Supplementary Fig. 1, on CheckV's gene counts. Keep a contig with viral genes, or with neither viral nor host genes, or with at least 75% unknown genes. CheckV's host trimming runs before clustering. The Methods' extra rule, length ≥ 1 kb, would keep nearly everything and is left out.

Island filter: genomad annotate on the vOTUs of 100 kb or more, then Antonio's pattern list from 10_filtering_3.sh. The paper names no tool, and its list is shorter.

Parity differences: no Guppy step, because SRA holds the basecalled FASTQ. Reads are pre-interleaved once on fir, so the plan carries no interleave step.

Datasets

  • 65 short-read metagenomes, one ENA run each: 31 from 2019, 34 from 2022. ENA's second run of H32 0.2 µm R1 (PNK108_H32_0_2) is left out, as the paper counts that sample once
  • 6 MinION runs, each reused across its well's 0.2 µm Illumina replicates: 17 hybrid assemblies
  • The Zenodo vOTU catalogue: 257,252 vOTUs of 5 kb or more. Each name carries its sample, assembler and caller

Driver

  • drivers/e3_pratama.py, all runs under one shared study root for the viral pool. 34 steps, solved locally on 2026-09-26
  • Assembly: bbduk → metaSPAdes, MEGAHIT and hybrid metaSPAdes on every run that has a MinION partner
  • Calling: geNomad, VIBRANT, VirSorter2 and DeepVirFinder on every lane's contig batches → one merge, each record named sample|lane|contig|span
  • vOTUs: CheckV in slices → keep rules and host trimming → MMseqs2 → representatives of 5 kb or more → island filter
  • Pratama's settings are pinned in library/transforms/e3. findings/E3_PARITY.md compares each step with the paper
  • Databases staged on fir: VirSorter2 2.2.4, VIBRANT, CheckV and geNomad, so no plan downloads one. geNomad's database is 1.5.1 against Pratama's 1.11.0

Targets / metrics

  • vOTU recovery by skANI at two levels: the pooled calls, and the final vOTU set
  • Per assembler and per caller, read from the published names: 113,105 metaSPAdes, 112,924 MEGAHIT and 31,223 hybrid vOTUs
  • Recovery, not identity

Proven

  • All 66 paired runs interleaved on fir: 9,521,730,640 records, twice the sum of runs.tsv read counts
  • VIBRANT, geNomad, CheckV, the candidate merge and MMseqs2: products inspected from live run d6UJuZgF
  • vOTU recovery method: a 65,640-row skANI table, from one sample and two of three callers
  • Wave 8 (Qt0rbV1R), the last run, which still carried the MAG half, completed QC, both short-read assemblies, the viral callers, the merge, CheckV and MMseqs2 on 65/65 runs
  • Wave 8's uncurated pool holds 4,597,542 contigs, against the paper's 4,717,962 before curation. MMseqs2 gives 3,292,226 vOTUs, 70,785 of them 10 kb or more (the paper has 82,807 before its island filter)
  • The viral lane is chunked rather than monolithic: CheckV runs per contig batch in about 35 minutes, where the monolithic run hit its wall
  • The home is archived to chinook (/Workspace_backups/Tony_Liu/fir_bench_e3/, 141,702 entries, 3.78 TB), verified by checksum resync. results/e3/RESUME.md holds the constraints a restore must keep to reuse the cache
  • The four viral gaps are closed in code, with 45 passing unit tests: the hybrid lane, DeepVirFinder's cut, VirSorter2's whole-contig boundaries, and curation with the island filter. The solve binds all 17 MinION inputs

Open

  • Stage the hybrid pairs before a relaunch. Wave 8 built only 6 of 17 hybrid assemblies: the given library keys inputs by path, so pairings that share a MinION file collapsed. Each pairing now gets its own hard-linked file, made by drivers/stage_hybrid_pairs.sh, which has not run on fir
  • No recovery number yet. A relaunch reuses wave 8's short-read assemblies and their geNomad and VIBRANT calls. It recomputes the hybrid lane, VirSorter2, DeepVirFinder and everything from the merge onward
  • Antonio's island list is broader than the paper's and matches case-insensitively, so parA also hits words such as "separation". Expect more than the paper's 562 removals
  • The paper's manual spot checks cannot be reproduced. Its six example contigs illustrate figures and are not a sample

metaGEM metabolic models

Goal: rebuild metaGEM's published genome-scale models from their published protein bins, on metaGEM's own CarveMe, DIAMOND and MEMOTE, and again on E5's GEM transforms for comparison with E5.

Datasets

  • metaGEM's 14,105 published protein bins, CheckM's Prodigal in single mode, from all five studies
  • metaGEM's 14,087 published GEMs, for the comparison
  • The reads (491 runs, 5.21 TB) are for E5, not E4

Driver

  • drivers/e4_gems.py --lane repro|modern, 7 chunks of 2,015 bins, run by drivers/e4_chain.sbatch
  • Reproduction lane, 4 steps: DIAMOND 0.9.30 database → --more-sensitive --top 10 → CarveMe 1.2.2 carve and gapfill on M8, CPLEX 22.2, 6 h, no retry → MEMOTE 0.9.13
  • Modern lane, 2 steps: E5's carveme_from_orfs (CarveMe 1.6.6, SCIP) → memote_score (MEMOTE 0.17.0)
  • Each finished lane is archived with its lineage index, and its cache entries and run directory are removed

Targets / metrics

  • Model count against metaGEM's 14,087, naming every missing bin
  • Per bin, against the published GEM: reaction, metabolite and gene Jaccard, and gene rules

Proven

  • Finished 2026-09-25. Reproduction lane 14,102 models, 14,088 MEMOTE results. Modern lane 14,097 models, each with a MEMOTE score
  • Both lanes built a model for all 18 bins metaGEM has no GEM for. Every bin either lane missed has a published GEM
  • Reproduction lane against metaGEM, median over 14,084 bins: reactions 0.840, metabolites 0.902, genes 0.976. 2.1% of shared reactions have a different gene rule
  • Modern lane against metaGEM, median over 14,079 bins: reactions 0.409, metabolites 0.531, genes 0.706

Open

  • No model matches its published GEM exactly. CPLEX 12.8 cannot be obtained, and carve on CPLEX 22.2 changes up to 25 reactions between reruns of one bin
  • The archives are the only copy of the models. A new plan recomputes every step

metasmith

metasmith optimized, piloted on 9 samples

Goal: show our best pipeline scores better where ground truth exists, finds more where it doesn't, and that the switch costs a definition change rather than a full rerun. The tool list is a starting point, and E1–E4 results will reshape it.

Decided

Annotation: the 4-lane panel replaces DRAM. Host prediction: iPHoP stays, since its database costs little. BLASTn spacer links are dropped.

Coverage: no CoverM. assembly_stats gives per-base coverage. phiX: no pipeline step. Check by hand when a sample needs it.

Plan keys: sharing keys with E2 and E3 is not needed for the design, but is wanted because reused steps cut runtime.

Datasets

  • Pilot: 3 samples each from CAMI, Pratama and metaGEM
  • CAMI 2+3: shows whether it's better
  • Pratama: shows whether the gain carries to real data
  • metaGEM, from reads: shows the model lane on real data

Driver

  • drivers/e5_pilot.py, one plan per corpus, because a plan gives every sample the same targets
  • Pilot samples: CAMI mouse gut, Pratama reads_2019 and metaGEM li2019. Every corpus registers the same study → sample → read pair shape
  • Wave 2, on the CarveMe 1.6.6 pin: CAMI u8oBvJrv, Pratama 35 steps (AvPNgFtP), metaGEM cSBSeNuq (which adds the interleave step). All three finished: 51, 381 and 85 models, each with a MEMOTE score. GTDB-Tk, GTDB-Tk de novo and iPHoP join with --with-gtdbtk
  • Wave 3 adds the dereplicators: CAMI P7FelAys (40 steps) and metaGEM BhEA2YLt (41) finished, with CheckM2, CarveMe and MEMOTE served from cache. Pratama waits on E3's run
  • Filters become masks: a frozen candidate set with thresholds applied as joins, not re-runs
  • Studies: a study is a corpus subset, such as CAMI II mouse gut or Pratama reads_2019. MetaPop runs once per study
  • Dereplication: DAS Tool, MAGScoT, dRep and skANI dedup are four interchangeable dereplicators over the same three binners' bins, each a sibling of the others. dRep and skANI run per sample and per study. MAGScoT kept 13–24 bins per CAMI sample and 35–43 per metaGEM sample
  • 4-lane annotation panel → CarveMe → MEMOTE → SMETANA
  • AMBER and skANI recovery run after the plan finishes, outside it

Targets / metrics

  • AMBER change vs E2 on CAMI
  • Recovery change vs E3 on Pratama
  • Model change vs E4
  • Cost: shared-prefix fraction reused from the parity caches, and task-hours saved

To decide after the pilot

  • Whether DRAM-v on the viral contigs goes with DRAM. It stays out of the plans until E3 reports
  • Whether minced stays. Its only E5 use was the BLASTn spacer links, which are dropped

Depends on

  • E2 and E3 landing, since their numbers are the baselines
  • New transforms: DeepVirFinder, MetaPop, SMETANA, and minced if it stays. Each also needs a container image. CheckM2, MAGScoT, dRep and skANI dedup are built and ran in wave 3
  • prodigal-gv on the frozen viral set now writes its own product type (bench::viral_orfs). Before that it answered DAS Tool's and MAGScoT's ORF input (B23), and DAS Tool failed on all 3 metaGEM samples
  • A study type that samples declare. viromics::contig_study stands in, grouping the viral merge and the per-study dereplicators
  • The 4-lane panel reads whole-assembly ORFs. Running it on MAGs needs a chunker for per-MAG ORFs
  • GTDB-Tk r232 needs its 199,923 representative genomes, which cost 427K inodes as files. They go into one squashfs image, and taxonomy joins the pilot once a GTDB-Tk run through the image passes
