One Frozen
Reference

Antonio's vOTU pipeline is a chain: every curation step writes a smaller FASTA, and every later tool reads whatever the previous filter left. Ported as-is, moving any threshold means re-running everything below it. So it is not being ported as-is. Three viral callers are reconciled into one candidate set, that set is frozen, and nothing after it writes sequence. Every tool downstream emits a table keyed on its contig ids — and the four filter scripts become a join you run afterwards.

The topology

One sequence-producing prefix. Everything after the line is a table.

Read it top to bottom. The first band is the metagenomics template the library already ships, unchanged. The second is the new part: geNomad, VirSorter2 and VIBRANT each report viral regions with coordinates, those calls are deduplicated and overlapping ones unioned from earliest start to latest end, and the result is pooled across samples into one object. That object is frozen. Below the dashed line every card hangs off it directly and produces only tables — no card feeds another, which is what makes them all leaves.

One thing in the picture is easy to miss and is the load-bearing part. The four per-contig annotators sit above the line, not below it. geNomad, VirSorter2, VIBRANT and DRAM-v report per contig; nothing about them is cross-sample, and a frozen contig is an interval of a contig they have already annotated — so they run once per sample and their tables reach a vOTU through the provenance table. Only the tools that genuinely need one pooled catalogue — MMseqs2, which defines a vOTU by clustering across samples, plus CheckV, vConTACT3, iPHoP and the spacer BLAST — sit below the line. That halves the number of heavy runs, and it is also what makes the graph solvable: see the note at the end of What it costs.

Why freeze

Set-dependence only bites if the set moves.

What the freeze buys

  • Thresholds move for free. The gene filter, the mobile-element filter, the 1 / 5 / 10 kb cuts and the vOTU slice are all a groupby over tables that already exist. A different cut costs a join, not a re-annotation.
  • The expensive tools run once. vConTACT3 has no way to reuse protein clusters on a subset — verified against the package, not the docs — so running it once on a fixed input is the only sane shape.
  • CheckV stops being a filter. It calls its own genes and its own HMMs, needs no prior viral call, and never drops anything: with no host boundary found it copies the contig through verbatim. Its contamination.tsv carries region_coords_bp, so the trim is a coordinate, not a cut.
  • One CheckV run, not two. end_to_end is contamination → completeness → complete_genomes → quality_summary over one shared prodigal-gv and DIAMOND pass. Steps 9 and 14 collapse into it.

What it costs, honestly

  • Every tool sees everything. With no size cut in the DAG, contigs Antonio would have thrown away at step 5 are still annotated. VirSorter2 over the full candidate set is the single most expensive item in the fan.
  • A sweep still is not a runtime knob. context.params is populated only from the Nextflow step metadata — cpus, memory, attempt — so existing params.get("min_length", …) calls in the library always take their defaults. Re-running the join outside the DAG is the sweep.
  • Abundance is derived, not re-mapped. Dropping CoverM means vOTU abundance comes from per-sample contig depth joined through the cluster table — the same logic bin depth already uses. A sample whose assembly missed a contig contributes zero for it, where cross-mapping would have counted its reads.
  • MetaPop is the one open question. It needs a directory of BAMs against one common assembly; the library's BAMs are per-sample against their own. Cross-sample microdiversity needs a mapping pass that nothing else in this design needs.
  • An annotation is computed on the parent contig, not the trimmed interval. The four per-contig annotators run per sample, so a provirus is annotated in the context of the host contig it sits in. For Antonio's gene-content rule that is the better input — the host genes it counts are on the untrimmed contig — but it is a real difference from running them on a curated vOTU set, and it will show in the comparison.
  • The freeze has to be one-way in the type system, not just on the page. Lineage constraints here are ancestral: the frozen set descends from every contig batch that fed the merge, so any requirement the frozen set also satisfies makes a caller's output eligible to feed the merge that produced it. The planner rejects the cycle, but it pays to find it, and not linearly — measured on this target set, with geNomad reachable on the frozen set the solve took 43 s; with VIBRANT reachable there as well it stopped finding any complete plan, returning zero steps in four seconds. That is why the annotators name sequences::contig_batch and every consumer of the frozen set names viromics::dereplicated_candidate_virus outright. An earlier draft of this design introduced a shared contig contract both satisfied; it is exactly the shape that reopens the cycle.

The three callers disagree on convention — geNomad appends |provirus_S_E, VirSorter2 ||full, VIBRANT _fragment_N, and CheckV adds _1 to a trimmed provirus. Reducing all four to one contig id and one interval is the whole substance of the merge.

Where this came from

A spreadsheet, fifteen shell scripts, and one Slack answer about thresholds.

The thresholds are not tuned. Asked in Slack on 16 June for a justification, Antonio answered that he followed the methods of one Nature Communications paper and that all of the thresholds were adopted from there. A corroborating detail: step 8's length ≥ 1000 is a no-op, because step 5 already cut at 1 kb — the signature of rules copied from a methods section rather than fitted to the data. Nothing on record shows hand-curation; “manually” meant submitting fifteen SLURM scripts one at a time.
