KBase in Fifty-Four Verbs

The KBase catalog publishes 493 apps over 121 workspace types with 2,758 declared parameters, and its users have left 1,633 distinct workflows behind. This round asks how many distinct things that actually is, and proposes the vocabulary a curated metasmith library would be built from.

01

KBase’s redundancy is in its vocabulary, not its science. 493 apps do 54 distinct things, 121 workspace types name 35 distinct kinds of object, and 2,758 declared parameters leave 262 real knobs.

02

That redundancy is mechanical, so a property grid removes it without judgment calls. Four names for a read library, min_contig_len beside min_contig_length, sixty-seven anonymous unions that are one entity with an axis left free. 64 of the 67 unions disappear, and the three survivors all belong to apps that accept any object by design.

03

What does not collapse is composition. 1,633 workflow shapes reduce only to 631, because a small vocabulary generates a long tail. But the head is short: 39 workflows cover half of everything anyone ran.

04

The blocker for a curated library is not vocabulary. Thirteen of the 54 verbs’ most-used implementation declares no typed output at all, and taxonomic classification has no workspace type anywhere in KBase. That is what stops a chain being asked for, and curation does not fix it.

The four axes

Where the count goes

Each row is one axis of the catalog, measured before and after the normalisation this round proposes. The bars are scaled within their own row, because the four totals are not comparable to one another — the ratio is the reading.

Apps

The core task vocabulary

A core task is the verb an app performs. Every one of the 493 catalog apps resolves to exactly one of these or to a named non-task, and the canonical method is the implementation the public narratives actually ran — the corpus picks it, not taste. consumes → produces is the proposal; where KBase’s own canonical app declares no typed product the row is flagged.

Three apps carry no verb

Types

One grid instead of 121 names

KBase names a concept once per era, once per container and once per measurement: KBaseAssembly.PairedEndLibrary beside KBaseFile.PairedEndLibrary, one Genome beside four kinds of GenomeSet, eight KBaseMatrices types that differ only in what the cells hold. Replacing that with an entity crossed with property axes is the shape src/metasmith_libraries/data_types/sequences.yml already uses.

The three survivors are not a modelling gap. Each belongs to an app that accepts every object type by design — KButil_copy_object, the staging exporter, and one viewer — so the rule falls out clean: every union that belongs to a science verb collapses.

Config

Most parameters are not knobs

Metasmith has no parameter primitive. A knob reaches a transform as a typed data item whose content is a config blob, so proposing a configuration ontology means proposing one config type per task and saying which of the 2,758 declared parameters belong in it. Most do not, and each of the others has a better home than a config blob.

The shared vocabulary

A knob earns a place here by being declared by at least two core tasks and meaning the same thing in each. maxaccepts taught the rule: twelve apps declare it and all twelve do homology search, so it is private to one verb rather than shared.

Workflows

A short head and a long tail

Round 1 reduced 3,965 public narratives to 1,633 distinct app sequences. Asked again over verbs — with plumbing and reporting steps dropped, and the remainder taken as a set because the corpus records cell order rather than dependency order — those 1,633 become 631 canonical workflows over 2,407 narrative copies.

Where it breaks

The source under-declares itself

Every gap below is KBase’s, not the planner’s. An app that reports its result instead of storing it leaves the chain’s end untyped, and nothing downstream can ask for it. This is the port’s dominant failure class, and the verb vocabulary localises it: it is not spread across 493 apps, it is thirteen verbs.

extract_bins_as_assemblies extracts assemblies and declares none. run_checkM_lineage_wf reports bin quality and declares none. align_reads_using_hisat2 and run_stringtie, the two most-run steps of every RNA-seq narrative in the corpus, declare none between them. A hand-written output override table for these thirteen buys more coverage than anything in the planner.

If it were built

What a curated library would look like

  • One transform per core task, in a directory named for its domain group, the way src/metasmith_libraries/transforms/ is already organised. 47 scientific transforms in place of 371.
  • Templates naming directories, not masks. The port ships one committed mask directory per template because 27 apps produce an Assembly and 46 require nothing at all. With one producer per type the ambiguity that forced the mask is gone.
  • Imports as deferred inputs, not transforms. This is the load-bearing bet and it is untested. The 46 pure sources are the cheapest producer of anything, which is why an unmasked solve answers every target with “import it from staging”. Making them template inputs removes them from the search entirely, and the qc axis stops an importer answering a target downstream of trimming. Neither claim is proved here.
  • Config as one typed item per task, carrying a YAML block with a median of four fields. The workflow catalogue is 631 YAML rows against one generic author module, in place of one Python module and one mask directory per workflow.

This round proposes and does not build. No transform, type or template was written. The deliverable is nine tables under research/kbase/curation/r2/ and a gate that reconciles every one of them against the port’s own census, catalog and round 1 shapes — never against itself. Rebuild everything with curate.py; it ends by running check.py, which exits non-zero rather than leaving the tables in a state that does not add up.
