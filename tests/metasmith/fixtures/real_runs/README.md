# Recordings of the authoritative runtime

## What goes in this file

What these recordings are and what they can be used to check. Nothing about the
change that prompted taking them.

## What this is

Metadata from two real Nextflow runs, taken out of the gitignored agent home at
`tests/metasmith_libraries/test_msm_home/runs/`. Nothing here is generated by a Python
test double: the `lin` line in `.command.metadata` is what `Orchestrator.groovy` actually
emitted, and it is the only checked-in record of the on-wire lineage payload.

Data files are excluded — only the metadata that describes them. Every absolute path
inside is a container path under `/msm_home/`.

`task_cache/*/manifest.json` is the CBOR shard manifest decoded to JSON for readability;
the store writes `manifest.cbor`.

## The two runs

`MBY6OPuI` is a single-step plan that ran. It has four invocation events in
`_metasmith/trace.jsonl`, one task's `.command.metadata`, the shard manifest that task
promoted, and the `results/_metadata/index.yml` and `given.csv` the run produced.

`UgSIdc2W` is a two-step plan that never executed. Its trace holds only the session
sentinel. Its `workflow.step_*.meta` records what a two-step compile looks like; nothing
else in it is a record of execution.

## The gap

Neither run records a task consuming another step's output. `MBY6OPuI` ran one step, and
`UgSIdc2W` ran none. So the shape of `PROV` when a staged input is a produced file — as
opposed to a given — is not witnessed here, and no assertion against these files can
cover it.
