## Notes on C16

C16 (duplicate-item replay) was sharpened to use two channels each emitting
the same file path through `postIn(..., fullHash=true)`. The hash collides
(both arrivals get the same content-hash from md5("$item") on the same path
string). The bag-insertion bug is real (`pending_groups.get(...).add(...)`
does no dedup), but the user-visible bag count is masked by
`_batch._batch.unique()` at output time (`Orchestrator.groovy:298`). So the
bag IS deduplicated by the time `.view` sees it.

This means C16 is a true-PASS today rather than a bug witness; Phase B's hash-
dedup at insertion time matches the visible behavior. The test still guards
against a regression where `.unique()` is removed or the index-history grows
unboundedly, so we keep it.

## Notes on C18 (potential post-fix shift)

C18 today is pinned as "1 wildcard emit" because lineage violation isn't
detected — b has no `a` key in its index but is still paired via the
WILDCARD-like cartesian path. After Phase B, the DESCENDANT branch's per-item
null check (B2) will drop b and log a `LINEAGE_VIOLATION` event. C18 may
need to be updated post-fix; this is acceptable behavior tightening.
